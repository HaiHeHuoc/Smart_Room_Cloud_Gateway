# `common` Component

## Purpose

`common` stores project-wide definitions shared by otherwise independent
components. It currently provides:

- application identity and release metadata through `app_common.h`;
- board and peripheral mapping through `board_config.h`;
- Kconfig-backed Firebase development macros used by application composition.

This component contains definitions, not feature logic or runtime ownership.

## Shared Configuration

- ST7735 resolution, SPI host, pins, speed, backlight, and transfer sizing.
- microSD mount point, SPI host, pins, speed, file count, and FAT allocation.
- DHT22 GPIO mapping.
- Active-low factory-reset GPIO and timing.
- `APP_PROJECT_NAME`, `APP_PROJECT_VER`, and `APP_PROJECT_VER_DATE`.
- Firebase macros mapped to local project Kconfig symbols.

## GPIO Mapping

| Device | Signal | GPIO |
|---|---|---:|
| ST7735 LCD | CS | 10 |
| ST7735 LCD | MOSI | 11 |
| ST7735 LCD | SCLK | 12 |
| ST7735 LCD | DC | 13 |
| ST7735 LCD | RESET | 14 |
| ST7735 LCD | Backlight | 15 |
| microSD | CS | 8 |
| microSD | MOSI | 16 |
| microSD | MISO | 17 |
| microSD | SCLK | 18 |
| DHT22 | Data | 4 |
| Factory reset button | Active-low input | 9 |

The LCD connection is write-only, so `LCD_GPIO_MISO` is `GPIO_NUM_NC`.

## Usage

```c
#include "board_config.h"
#include "app_common.h"

ESP_LOGI(TAG, "%s v%s", APP_PROJECT_NAME, APP_PROJECT_VER);
```

Typical users:

- `display_driver`: LCD bus and panel definitions;
- `ui_manager_lvgl`: resolution and draw-buffer sizing;
- `sd_card_manager`: microSD bus and mount configuration;
- `sensor_DHT22`: DHT22 data GPIO;
- `button_manager`: factory-reset GPIO and timing;
- `main`: application identity and Firebase composition values.

## Firebase Development Configuration

`app_common.h` maps the following macros to values generated by project
Kconfig:

```text
FIREBASE_API_KEY
FIREBASE_DEVICE_EMAIL
FIREBASE_DEVICE_PASSWORD
FIREBASE_DEVICE_UID
```

The real values are entered through `idf.py menuconfig` and stored in local
`sdkconfig`, which is ignored by Git. Current source does not contain real
Firebase account values.

The generated values are still compiled into development firmware. Do not
publish `sdkconfig`, credential-bearing firmware binaries, or logs containing
passwords or tokens.

See:

- [`firebase_auth` setup and security](../../../cloud/firebase_auth/docs/FIREBASE_SETUP_AND_SECURITY.md)
- [repository security policy](../../../../SECURITY.md)

## Important Notes

- LCD uses `SPI2_HOST`; microSD uses `SPI3_HOST` in the current board mapping.
- `LCD_LVGL_DRAW_BUF_LINES` is a partial draw-buffer row count, not the display
  height.
- `SD_CLOCK_KHZ` uses kHz because ESP-IDF SDSPI host configuration expects kHz.
- Keep pin changes centralized in `board_config.h`.
- Verify replacement GPIOs against flash, PSRAM, USB, strapping, and other
  project peripherals.
- `APP_PROJECT_VER_DATE` is manually maintained and is not build-generated.

## Future Attention

- Split configuration by board revision when additional variants are supported.
- Move deployment-specific endpoint and device identity into a dedicated
  deployment configuration.
- Add protected per-device credentials before a production release.
- Keep Wi-Fi, BLE, cloud, UI, and application workflow logic out of this
  component.
